# 감지 알고리즘

## 기본 아이디어

절대 거래량이 아니라 **그 코인이 평소 흔들리던 폭 대비 얼마나 벗어났는가**를
측정한다.

같은 500이라는 거래량도

- 평소 100 근처에서 조용하던 코인이라면 큰 사건이고
- 평소 80~300을 오가던 코인이라면 평범한 일이다

절대값으로는 이 둘을 구분할 수 없다. 그래서 기준선과 그 기준선 주변의
정상적인 흔들림 폭을 종목마다 따로 잡고, 현재 값이 그 폭을 몇 배나
벗어났는지를 본다.

## 계산 절차

### 1. 현재 속도

```
v = 현재 창의 누적 거래대금 / 경과 시간(분)
```

거래대금을 그대로 쓰지 않고 분당 속도로 나누는 이유는, 봉 마감을 기다리지
않기 위해서다. 4시간봉이 시작 6분 만에 터졌다면 6분치 거래대금을 6으로 나눠
곧바로 판정한다.

### 2. 기준선 (중앙값)

```
M = 직전 N개 창의 속도들의 중앙값
```

N은 프레임마다 다르게 잡는다. 아직 미확정.

### 3. 변동 폭 (MAD)

```
D = median( |각 창 속도 - M| )
```

표준편차가 아니라 MAD(median absolute deviation)를 쓴다. 이유는 아래 참고.

### 4. 점수

```
S = (v - M) / D
```

"평소 흔들리던 폭의 몇 배만큼 위로 벗어났는가"를 뜻한다.

D가 0에 가까우면 S가 발산한다. 완전히 잠들어 거래가 거의 없는 종목에서
실제로 발생한다. 중앙값에 비례한 하한을 두는 방식이 유력하지만 계수는
아직 미확정 (`MAD_FLOOR_RATIO`).

### 5. 퍼센타일 환산

S를 해당 **심볼·프레임**의 과거 S 분포에 넣어 백분위로 바꾼다.
분포는 심볼마다, 프레임마다 따로 관리한다. BTC의 S=4와
잡코인의 S=4는 전혀 다른 사건이기 때문이다.

### 6. 판정

```
백분위 >= 사용자 민감도(1~100)  ->  알림
```

민감도 95는 "이 종목·이 프레임의 과거 분포 기준 상위 5%에 드는 사건만
알린다"는 뜻이다.

## 왜 평균/표준편차가 아니라 중앙값/MAD인가

거래량 분포는 오른쪽으로 심하게 치우쳐 있다. 대부분의 시간은 조용하고
가끔 극단적으로 큰 봉이 하나 튀어나온다.

평균을 기준선으로 쓰면 그 큰 봉 하나가 기준선을 통째로 끌어올린다.
그 뒤 몇 시간 동안은 웬만한 급등이 와도 "평균보다 낮음"으로 판정되어
알림이 아예 안 뜬다. 정작 큰 사건이 터진 직후가 후속 움직임이 가장 활발한
구간인데, 바로 그 구간이 통째로 먹통이 된다.

표준편차도 같은 문제를 겪는다. 편차를 제곱하기 때문에 극단값 하나가
분모를 크게 부풀리고, 그러면 이후 모든 점수가 눌린다.

중앙값과 MAD는 극단값에 흔들리지 않는다. 관측치 절반이 통째로 바뀌기
전까지는 기준선이 유지된다.

## 왜 배수가 아니라 퍼센타일인가

"평균 대비 3배"라는 설정은 두 가지 문제가 있다.

첫째, 사용자가 그게 얼마나 센 건지 감을 잡을 수 없다. 3배가 하루에 한 번
울리는 값인지 백 번 울리는 값인지 알 수 없다.

둘째, 같은 3배가 코인마다 전혀 다른 의미다. 변동이 큰 종목에서는 일상이고
조용한 종목에서는 사건이다. 결국 종목마다 사람이 값을 다시 맞춰야 한다.

"상위 5%"는 두 문제를 동시에 해결한다. 울리는 빈도가 사전에 예측 가능하고,
분포가 종목별로 따로 잡히므로 하나의 설정값이 전 종목에 그대로 적용된다.

## 필수 필터

점수만으로 알림을 내면 쓸모없는 알림이 대량으로 발생한다. 아래 네 가지는
선택이 아니라 필수다.

### 최소 거래대금

잡코인의 거래대금이 1만원에서 20만원이 되면 S는 폭발한다. 통계적으로는
확실한 이상치다. 그런데 실제로는 진입할 수 없다. 호가가 비어 있어서
주문을 넣는 순간 본인이 가격을 만든다.

절대 거래대금 하한선으로 자른다. 통계와 무관한, 순수하게 실행 가능성
기준의 컷이다.

### 시간 감쇠 쿨다운

한 번 터진 종목은 그 뒤로도 한동안 계속 시끄럽다. 그대로 두면 같은
사건으로 알림이 수십 개 나간다.

알림 직후 임계치를 일시적으로 올리고, 수 분에 걸쳐 원래 값으로 되돌린다.

**"직전 알림보다 큰 거래량이어야 함" 방식은 쓰지 않는다.** 이 방식은
큰 폭발이 한 번 나오면 기준이 그 높이에 계속 머문다. 그 뒤에 오는 새로운
사건은 아무리 의미 있어도 첫 폭발보다 작으면 영영 안 울린다. 시간이
지나면 기준이 원복되는 감쇠 방식이어야 새 사건을 놓치지 않는다.

### 봉 시작 직후 최소 경과 시간

`v = 거래대금 / 경과분`에서 경과분이 0에 가까우면 v가 발산한다.
창이 열린 직후 체결 한 건만 들어와도 속도가 무한대로 튄다.

각 프레임마다 최소 경과 시간을 두고, 그 전에는 아예 판정하지 않는다.

### 프레임 중복 병합

1분봉이 터지면 5분봉과 15분봉도 대체로 같이 임계를 넘는다. 같은 사건이
서로 다른 창에 잡힌 것뿐이므로 알림 세 개를 보내면 안 된다.

일정 시간 창 안에서 같은 심볼의 후보들을 하나로 묶는다. 그리고 겹친
프레임 수를 버리지 않고 **신호 강도**로 표시한다. 1분봉만 터진 것과
1분·5분·15분·1시간이 동시에 터진 것은 사건의 크기가 다르다.

## 데이터 소스

바이낸스 **aggTrade** 실시간 체결 스트림을 받는다. 체결을 1초 버킷에
누적하고, 버킷을 롤링 합산해서 모든 타임프레임을 1초 해상도로 평가한다.

kline(봉) 스트림만 쓰면 안 되는 이유는 명확하다. 1분봉 스트림은 봉이
닫혀야 확정값이 나오므로 감지가 최대 60초 늦는다. 급등 알림을 60초 뒤에
받으면 이미 진입 구간이 지나 있다. 단타 도구로서 의미가 없다.

**봉 마감을 기다리지 않는다.** 4시간봉이 시작 6분 만에 터져도 6분치
속도로 즉시 판정한다.

## 미확정 파라미터

아래는 전부 백테스트로 결정한다. 지금 `packages/core/src/constants.ts`에
`TODO(backtest)` 주석과 함께 임시값만 들어 있다.

| 파라미터 | 상수명 | 무엇을 정해야 하나 |
|---|---|---|
| 룩백 창 개수 N | `LOOKBACK_WINDOW_COUNT` | 작으면 기준선이 흔들리고 크면 장세 전환에 늦다 |
| 최소 경과 시간 | `MIN_ELAPSED_SECONDS` | 프레임 길이에 비례시킬지 고정값으로 둘지 포함 |
| 최소 거래대금 하한 | `MIN_QUOTE_VOLUME` | 거래소·견적통화별로 다른 값이 필요 |
| 쿨다운 지속시간 | `COOLDOWN_DURATION_SECONDS` | 프레임별로 얼마나 길게 |
| 쿨다운 감쇠 곡선 | `COOLDOWN_DECAY_CURVE` | linear는 초반에 빨리 풀리고 exponential은 꼬리가 길다 |
| 쿨다운 초기 상향분 | `COOLDOWN_INITIAL_BOOST` | 백분위 포인트 단위 |
| 퍼센타일 데이터 기간 | `PERCENTILE_HISTORY_DAYS` | 짧으면 표본 부족, 길면 옛 장세가 섞임 |
| 최소 표본 수 | `MIN_PERCENTILE_SAMPLES` | 이보다 적으면 알림을 내지 않는다 |
| 프레임 병합 창 | `FRAME_MERGE_WINDOW_SECONDS` | 같은 사건으로 볼 시간 범위 |
| MAD 하한 계수 | `MAD_FLOOR_RATIO` | 잠든 종목에서 S가 발산하는 것을 막는다 |

백테스트에서 봐야 할 지표는 두 가지다. 민감도별 실제 발생 빈도가
의도한 값(상위 N%)과 맞는지, 그리고 알림 이후 실제로 의미 있는 가격
움직임이 뒤따랐는지.
